## Manifest repair

[The upstream manifest](../manifest/cm-10.2.0-upstream.xml) used a moving stable branch for most CM projects even at the release tag. The recovered manifest pins surviving release tags first, then resolves remaining stable references. It preserves AOSP Android 4.3.1 pins, checks the CTS fallback against the AOSP `android-4.3.1_r1` tag, and uses the same AOSP tag for the inaccessible CM SVOX entry. Unavailable `notdefault` IDE/SDK authoring projects were omitted. The Galaxy S5 kernel and G2/Togari MDSS and V4L2 dependencies were added. The original CM BasicSmsReceiver is superseded by the staged project source. [Git ref inventory](../manifest/upstream-refs.tsv)

## Interface decisions

- **Boot and storage.** Keep S5's board DTS, kernel, 2 KiB boot pages, DT table, partition labels and CM11 boot offsets. The G2 also uses separated DT packaging, with different ramdisk and tags addresses. Use S5's target ramdisk data and adapt the CM11 `sdcard` command line and USB/microSD fstab records to the Jelly Bean daemon and vold syntax. Jelly Bean init understands `mount_all`; it lacks CM11's `restorecon_recursive`. Port and audit the target file labels before device use.
- **Graphics.** G2 and Togari have open Jelly Bean MDSS HWC/gralloc and V4L2 media sources. Use both at the OS revision. Compare `msm_mdp.h`, ION heap IDs, buffer layout and fences against the S5 kernel before accepting frame, compositing or codecs as working. The S5 uses the MSM8974AC board DTS and Adreno 330. Its GPU name alone does not establish EGL binary compatibility.
- **Audio.** Start with G2's JB CAF HAL and the S5's mixer and routing tables. Check card names, ACDB IDs, offload capabilities and audience firmware before validating playback or recording.
- **Radio.** Preserve API 18's `Phone`, TelephonyProvider, Stk, rild and APN/SPN configuration. CM11's unified GSM build used `KlteRIL`, while Verizon used `SamsungQualcommRIL` with separate subscription and network mode defaults. The new products start with the CM10.2 RIL code and variant settings. The target parcel formats, preferred network mode calls, SIM status, unsolicited responses and data calls need comparison before choosing a narrowly scoped RIL adapter. LTE attach and SMS delivery have distinct validation steps.
- **Camera, sensors, GPS, charging and power.** Use Samsung CM11 target configuration and target-owned firmware. Camera HAL and stagefright interfaces need separate comparison against JB; Sony's JB camera approach is an independent comparator. Preserve kernel battery/thermal support and qualify the target thermal daemon before any sustained hardware test.
- **Product behavior.** CM10.2 splits Dialer and Mms from Phone and Contacts. T-Mobile uses the default handset product, the K7-style per-variant framework capability flags, a CM APN list and Crystal BasicSmsReceiver. The original app's `Telephony.Sms.Intents.getMessagesFromIntent` is present in CM10.2 `telephony-common` and uses the broadcast's `format` field. The port uses a Holo dialog. Settings keeps mobile networks when ConnectivityManager exposes a mobile network, and selects “About phone” from the default resource product.
- **CrystalGram Holo.** The published app identifies API 16–18 and d2vzw/CM10.2 as its original platform. Keep the OS ABI and application environment for a later install-and-use check. The signature-spoofing source for the existing CM10.2 Crystal implementation has not been verified. microG remains a follow-up and is absent from the initial build.
